# A passed fixture is not a passed running preview

Validation should name the exact boundary it exercised. A Debug button download through a local signed-in fixture proves the UI/account route/ZIP chain with real PG, not the user's deployed registry configuration. A scripted answer/SSE race proves pairing without buying another model answer. A final-package browser download can use the actual zero-model producer and verify every manifest hash without rerunning generation.

Keep these proofs separate from anonymous health/browser checks against the running preview. Optional private browser state can check an existing account's Debug ZIP there. Never turn missing authentication or an absent existing run into a green result. Never create live tasks, change own-test settings, click Stop/Delete, submit an answer or begin generation just to prove a hurdle.

The runner strips caller live settings/secrets for fixtures, starts disposable PG through the existing harness and blocks off-machine Python socket connections. Browser races use scripted responses. Artifacts use a private output folder rather than a system-specific /downloads path. Missing tools/config and red tests fail; skipped cases print NOT CHECKED.
