# One public pin store, one operator review flow

Back office Model pins replaces the separate launcher price generator/cache. Durable append-only revisions plus current heads are needed for restart-safe prices/defaults and an operator audit trail; code/config alone cannot give all processes the same reviewed version. Every commit checks services.operate in protected config, current session and the enabled database registry. This capability is not granted automatically. The schema batch also grants restricted runtime SET membership in the editor role. No keys are stored in pins.

Refresh uses fixed public provider sources, shows a diff, and requires Approve default. Manual edits use the same validator/commit and retain fetched_at. Stale pins warn; failed refresh below24h warns, at24h/errors/missing prices block paid work. Stored prices do not renew on failure. Reviewer reason and old/new immutable revisions survive restart. No background automatic approval.

Each task generation retains its resolved price/context snapshot in existing owner-scoped decision_reviews. Jobs reconstruct the same gateway even after a current pin changes or the process restarts. New task generations use the current default. No edits to historical quotes or settlements. Current support remains DeepSeek/Ollama; adding a provider needs its accounting adapter, not just a row.

Compatibility: additive tables and role, no task/data deletion. Owner runs one reviewed migration batch, with separate exact hash confirmation for the capability-constraint widening. Existing #616 migration file remains separate and is not rewritten. Whether both appear in one pending batch depends on the owner's schema output. Forward repair disables services.operate or leaves pin heads unchanged; never deletes revision/audit evidence. Fresh-install/upgrade runner and restricted-role tests cover SQL.

Preview starts its UI even if execution is closed so pins can be repaired. Own preview container replacement requires exact name/image/data-volume/loopback-port identity, TERM and observed exit; no force kill or volume removal. Unknown listener/container remains a data-safety error. req debug exports bounded scrubbed container log and failure/build facts without env/argv/DB reads. Unexpected nonzero cleanup captures before deleting temp state. Installer now installs a symlink instead of a copied req.

Operator rollout prerequisite: services.operate must be deliberately enabled for the sole operator in both the DB registry and protected operator capability setting. This feature does not infer it from admin or add it automatically. Without it the page explains access is unavailable; owner setup must grant the reviewed capability. Need `req preview --apply` schema/readiness output to know whether #616's migration was already applied; pending files remain one exact reviewed batch either way.

Terminal severity display: req/preview wrap output only when attached to a TTY and NO_COLOR is unset. Error/abort/failure lines red, warnings yellow, including engine output passing through preview. The wrapper preserves the inner exit code. Pipes/files/debug ZIPs stay plain. No independent engine logging/format path was added.

Owner correction supersedes the earlier preview approval design: customers see credits only, with no provider USD dialog or customer approval endpoint. Infrastructure ceilings are immutable operator policy revisions edited in Back office with explicit reason/confirmation; absent policy blocks paid dispatch privately. Every DeepSeek dispatch checks settled actual plus outstanding full-context worst-case holds per task generation under the existing global/owner lock. No amount or activation is inferred. Historical approval migration remains untouched.

Debug evidence measured 18.759s for the eleven serial manifest requests alone, with client/server difference only6-8ms per read. Existing physical pool already reuses connections; transaction/security/query round trips remain expensive. A fixed server collection replaces those eleven HTTP requests with one bounded request and one scoped connection, per-source savepoints and unchanged capability/role checks. Capacity timelines and day aggregates are batched, not N+1. Each source emits elapsed time and statement count. No sleep or faster polling is added. Broker non-200 diagnostics now record only safe status and allowlisted provider error codes; unknown outcomes stay uncertain and are never automatically retried.

Separate baseline bug repaired: the main branch had retired force-job closure in d89ff00 but left Back office controls/proxies and service calls to deleted store methods. Remove stale controls/proxies, return explicit410 without mutation for bookmarked service routes. Do not resurrect administrative job closure or add a parallel recovery path. Normal Stop remains unchanged; owner preview reset remains separate reviewed work.
