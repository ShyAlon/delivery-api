# Paid acceptance is a separate owner action

A green fixture suite is not a live paid acceptance run. The owner script must use the real signed-in API and browser, immutable test marking, approved model pin and existing server ceiling, then inspect actual cost before purge. Dry mode performs authenticated GET requests only and never signs in, creates a task or contacts a provider.

The graph can request structured input instead of an interview question. Never blindly approve it to keep a test moving. Keep the task and diagnostic evidence on failure or unsettled cost. Vendor expense is not the customer retail charge: read exact settled expense with its scale through an owner-test-only route, and keep unknown values unknown. The script never changes the server ceiling and refuses when it exceeds the explicitly supplied approved amount.

The fixture tests prove orchestration, dry-mode no-write behavior, ceiling refusal, marker-before-Start, one answer, no implicit purge, unsettled retention and no arbitrary approval. They do not prove the real paid journey succeeds. No paid execution was done. The live pin-derived numeric estimate still needs the authenticated owner preflight.
