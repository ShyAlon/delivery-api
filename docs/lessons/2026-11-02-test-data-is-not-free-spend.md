# Test content and real money are separate

A hands-off acceptance run must never mix test work with product lists or exports, and must not hide real costs from balances or admission. An immutable creation-time test marker lives on the task identity retained by every job and cost row. Normal lists exclude it; the reviewed owner has a separate test view. Product artifact/package exports refuse test content. Operational money and audit reports deliberately include real test charges.

The migration adds a narrow SECURITY DEFINER purge function, never broad DELETE grants. It only accepts the enabled reviewed operator with sessions.operate, their own immutable test task, explicit confirmation, durable Start+answer operations, all jobs done with reaped completion evidence, no lease and no unsettled money/compute. Failure, unknown content scope, source directories or private revision lineage refuses atomically.

Successful purge deletes bounded DB content/checkpoints/artifacts and progress. Shared artifact bytes and threads are protected. Minimal task/session/job identities and immutable money/audit survive with the test tag. No direct deletion of live data is performed by the implementer. The owner must apply the migration before using the route.

These controls are for the child acceptance path. A normal Delete remains Stop/hide and is not this purge. Existing operational logs are audit evidence, not silently scrubbed. Future product analytics must filter tasks.is_test; do not reuse accounting totals as product metrics.
