# Runtime is not a location mode

Problem: preview, cloud, attended and child flags chose different execution and
artifact behavior for the same task. A green local path could not prove the
remote path, and a settings change could revive an obsolete compatibility path.

Change: construct the child runtime from reviewed durable provider/model pins at
every origin. Configuration supplies addresses, credentials, limits and model
values. Construction is not spending authority. Owner admission, prepaid
balance, reviewed quotes, expense ceilings, settlement and tenant/session claims
remain enforced at dispatch. Stop still terminates and reaps the child.

Acceptance must use one signed-in identity and journey contract, changing only
the target URL. Test with real child processes and disposable PostgreSQL, with
external provider HTTP replaced, rather than changing execution logic by host.
Keep a names-only configuration inventory and an explicit ban on retired mode
reads so new configuration requires review.

Separate follow-through: artifact transition switches and legacy storage/auth
branches belong to the DB-only cleanup; old server rollout scripts belong to
the one-image/digest workflow replacement. Neither is proof of deployed parity.
Do not run a migration, deploy, contact the server or make a paid call to prove
this refactor without separate owner authority.
