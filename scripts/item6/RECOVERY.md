# Exact stopped-run recovery

This is private local recovery, not a production route or a clean acceptance rerun.
The original container, dump, interview files, and INCOMPLETE status stay intact.

## Accounting

The read-only preview binds original owner, auth session, task, failed job, raw usage,
quoted snapshot, historic dispatch-to-received-usage interval, and prepaid account.
Approved apply restores a fresh isolated working database, rechecks sources, and
posts the exact token contribution/debit once. The original job remains failed.
It does not retry the model request or create another purchase.

Unknown deterministic compute is explicitly waived with an audit recording
measurement=unknown, disposition=waived, billed_units=0. deterministic_ms and
settled_at stay NULL. It is not fabricated as a measured zero duration.

Approval of build work is not approval of the accounting amounts or paid execution.
Apply requires the canonical preview digest, original archive hash and source checks.

## Linked continuation

A separate reviewed continuation binds reconciled archive hash, original checkpoint
and semantic-review file hashes, runtime catalog/context hashes, exact task/job, and
maximum additional provider-expense units. There is no automatic resume.

The original artifacts are copied to a new private working tree. All SQLite WAL
sidecars are preserved. The resolved semantic decisions and intent must match before
a new writer job regenerates the whole CONOPS node. It skips the earlier interview,
uses new concept/approval review IDs, and follows the existing generator and closed
Gate/Edit review flow. It does not reuse old gate approval for new content.

The predecessor stays failed. Completion is CONTINUATION_EVIDENCE_READY, never
ACCEPTANCE_EVIDENCE_READY. Original uninterrupted acceptance remains INCOMPLETE,
launch_authorized=false. All new jobs must finish and all accounting must resolve.
A later fresh uninterrupted acceptance run needs its own approval.

## Bounded hardening

Only public vendor-document GET failures receive up to three total attempts with
1s and 2s waits. Hash/content/schema disagreement stops immediately. No model POST
retry or skipped source validation. Exhaustion retains raw usage and held accounting.

## Scope limits

Original data is immutable. Restore targets only a new local database. A successful
public connectivity check does not prove the earlier fault's cause or external
provider debit. Real raw usage proves received provider usage, not an invoice.
The settlement-path source fetch is a code-path explanation, not a proven network
root cause. Diagnostic/operator approval does not authorize new provider spending.

## Exact interrupted continuation

The private version-2 route restores only the exported `ea2b834...` archive and
its pending concept choice `51cb41b...`. It keeps the nine already settled new
calls in the cumulative $1.00 provider cap. Only the original failed job is
excluded from that cap. It verifies the two exact failed predecessors, 76
settled attempts, $0.005264388 new provider expense and 3.1954875-credit balance
before an explicitly authorized unknown-compute failure waiver. No new tokens
are posted for the pending choice, and no CONOPS regeneration or interview
replay is performed. The exact original InputRequest is checked against the
saved draft, typed options, rationale requirement and session evidence before
it is shown again. A founder must still choose and supply the rationale.
Both failed jobs remain visible; completion cannot claim uninterrupted
acceptance. A new failure exports evidence and requires another explicit
recovery decision, never an automatic restart.

## Unknown provider failure and generator checkpoint recovery

An explicitly authorized unknown provider call is recorded as `failure_waived`,
not a fabricated zero-cost settlement. Usage, provider actual expense, retail
actual and settlement timestamps remain NULL. Its pending charge is explicitly
waived, without a customer debit or token contribution. The failed worker remains
failed. Its original conservative expense reservation continues to count against
both owner allowance and the original cumulative continuation cap.

The private wire audit stores attempt/job identity, exact response SHA256, byte
and line-ending counts, event count, terminal token counts, DONE and bounded error
class. It never stores keys, requests, prompts or complete responses.

Generator recovery validates copied checkpoint/WAL, prior canonical artifacts and
saved baseline. Only a saved architecture next-task may invoke with no new graph
input. It preserves accepted intent/CONOPS/SRS and does not repeat their gate.
The new generator still waits at the architecture gate and normal later reviews.
The runner now wires per-item partial persistence for future interruptions. If
an older interrupted run has no architecture partials, paid recovery can repeat
architecture calls; that fact must be named in its separate exact paid review.

Top-up preparation is sandbox-only and separate from generator recovery. It uses
an immutable new purchase ID and stable create/capture request IDs against the
existing nonzero credit account. Pack, amount and runtime are reviewed before
network work. Buyer approval is not proof of payment: capture and signature-verified
webhook reconciliation are required, with once-only credit posting. No manual
credit grants, live activation, original-order replay or cap reset. Any partial
payment work exports a private ledger dump and must be reconciled before another
purchase or recovery. A top-up does not authorize paid generator execution.

When approved write-off and top-up are both needed, use one restored ledger and
one exported successor dump. The top-up entry can include the separately
source-authorized failure waiver before payment work. Do not apply them to two
independent restorations and then discard either successor ledger. Export and
reconcile any partial order on the same ledger before paid generator review.
