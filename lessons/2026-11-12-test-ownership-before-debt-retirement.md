# Test ownership before debt retirement

Old backlog descriptions can outlive their defects. Reproduce current callers
first. A shared migrated database is not isolation when one browser suite leaves
operator grants and credits behind. Give that suite its own database and prove
cleanup after failure. Construct real stores and replace only the inspected SQL
boundary rather than copying constructor state into __new__ doubles.

Do not fix a full-package browser failure by hiding the missing session: preserve
saved artifacts and translate the known absence at the typed child-read boundary.
Keep unrelated snapshot serialization errors visible. Reuse the explicit store
operation registry rather than introducing another transaction registration path.

Observe both valid decision states: auto-opened route or a live launcher. Waiting
only for one can race. Test and activate the launcher in one browser turn, then
wait for the actual route. On failed send, restore the original question's
visibility only if the submitting render still owns the page. Pixels can still
show stale progress even after the composer assertions pass; keep that separate
remaining defect visible instead of calling the whole UI done.

Final source-enabled fast coverage also exposed two ownership assumptions. The
network guard must launch this run's installed interpreter, not demand a second
sibling virtualenv. Watchdog stop must join the sampler it owns, not just set a
flag and race the next assertion. The immediate thread-exit test failed before
the fix. Shutdown is bounded and never joins itself.
